## B. Audit / maintainability (no behaviour change)

**B1. `core/ui.py` is now 951 LOC — the split is overdue** `[M]` — the Grand Audit
flagged this at **796**; it has since grown to **951** (the single largest non-test
file, 22 top-level defs/classes mixing spinner, art, health display, prompts, and
queue UI). The recommended split into a `core/ui/` package (`spinner.py`, `art.py`,
`prompts.py`, `display.py`) is now more urgent and still pure-mechanical — no
behaviour change, re-export from `core/ui/__init__.py` to keep imports stable. Do it
**before** any web-layer adapter lands. *(This is the prior audit's §B3, re-confirmed
and re-prioritized, not a new feature.)*

**B2. Audit the 31 silent `except … : pass`** `[S–M]` — the broad-except count nearly
doubled (93 → 177) and the **silent** subset went from ~18 to **31**. Per the ruff
config note, broad excepts around network/LLM calls are *intentional* (one failing
provider must not crash discovery) — the smell is the **silent** ones that can hide a
programming error. Walk the 31, ensure each at least `log.debug(...)`s, and leave a
one-line "why broad" comment. No new `try` scopes — just make the existing ones
honest. Aligns with the roadmap's open "annotate/retire broad excepts" item.

**B3. Large-module cohesion review** `[M]` — after `ui.py`, the next size outliers are
`content_engine.py` (730), `llm_router.py` (648), `best_bet.py` (610). Not a rewrite —
a read-through to confirm each still has one job and to note any obvious seam (e.g.
`content_engine`'s prompt-assembly vs. the inject/reground passes). Audit output is a
note, not a refactor PR.

**B4. Recommender duplication note** `[S]` (audit only) — `best_bet.py`,
`length_recommender.py`, and `analytics/post_timing.py` are documented as sharing
"one pattern" (analytics-source-else-default + rationale string + confidence tag).
Confirm whether that pattern is actually shared code or copy-paste; if copy-paste,
log it as a future `recommender_base` extraction. *Flagged as debt, not actioned —
extraction would be a structural change better done deliberately.*

## C. Efficiency (cheaper / faster, same output)

**E1. `obsidian_facts.load_facts` reads the whole vault every run** `[S]` — still
`vault.rglob("*.md")` on every discovery (Grand Audit §A, still open). At small vault
sizes it's fine; add an mtime-keyed index (`{path: (mtime, parsed)}`) so unchanged
notes aren't re-read/re-parsed. *Saving: scales the connector to a large vault without
a per-run full scan.*

**E2. Web-search double-cache** `[S]` — the signal-internal cache and the
`register_signals` cache share a key (Grand Audit §A: "redundant but harmless").
Collapse to one lookup. *Saving: one fewer cache round-trip + half the stored
payload for the web-search signal.*

**E3. Signal circuit breaker has no re-probe TTL** `[S–M]` — `register_signals` has
per-signal *cache* TTLs but the session breaker (`_SESSION_DISABLED`) has no
re-enable: a transient quota blip at hour 1 of a long-lived `jobs.worker` disables a
signal until restart. This is exactly **O10 (reset-window auto-re-enable)** in
[credit_efficiency.md](credit_efficiency.md) — listed here as the *audit* finding that
motivates it. *Saving: recovers usable quota the breaker would otherwise waste for the
rest of a worker session.*

**E4. Split heavy render deps so logic tests run lean** `[S–M]` — `moviepy`,
`elevenlabs`, `psycopg2-binary`, and the Google API client are **core** install deps,
so a fresh env can't even *collect* the pure-logic tests (see caveat above), and CI
pays a full media-toolchain install to run them. Move the render/upload/DB libs behind
extras (`[render]`, `[publish]`) and give the logic suite a lean `[test]` path, or
guard the moviepy import so collection survives without it. *Saving: faster CI, and
the test suite becomes runnable in minimal environments — directly fixes why it
couldn't run here.*

**E5. `moviepy==1.0.3` wheel build is fragile on modern Python** `[S]` (audit) — it
failed to build in this 3.11 env. CI pins 3.11 so it presumably works there, but the
dependency is unmaintained and a reproducibility risk. Note it for a future bump to a
maintained fork or a thinner ffmpeg wrapper (the codebase already shells out to
ffmpeg directly for the render command). *Flagged, not actioned — a dep bump needs a
real render test.*
