## 0. Verdict

Six days ago the finding was *the checks report healthier than the system is*. Today
the four checks that matter most are enforced by a command rather than a paragraph:
the suite's verdict is independent of test order and CI proves it on every push; a
partial install says so in one line; mypy can fall but not rise; and every doc carries
a card, an index row, a size ceiling and a naming rule that the lint checks. The
product did not move this wave — deliberately. The learning loop is still volume-
starved and both ranking scores are still anti-correlated with engagement at n=12
(backlog #819/#824); that is [master_plan.md](master_plan.md) M4 and the roadmap's next
five, and nothing structural was allowed to displace it.

One correction to the record. The 09-20 audit attributed the order-dependent
`test_run69_fixes` failures to a module-level probe cache. The cache class of leak was
real and is now closed (§1.2), but *that* symptom had a different cause (§1.1), and the
cause explains why the operator's fully-installed box never saw it.

## 1. Test integrity

### 1.1 The order-dependence, root-caused

`tests/test_ops_doctor._stack()` built an `ExitStack` of a dozen `patch()`es **outside** a
`with` and returned it. When a later target failed to import — `youtube.oauth`, on any
box without `googleapiclient` or a working `cryptography` — `_stack()` raised before the
`with` ever received the stack, and the patches already entered were never exited.
`core.run_mode._ollama_ready` stayed a mock returning `(False, None)` and
`free_backend_readiness` a `SimpleNamespace` for the rest of the process: exactly the
values in the five failing assertions (`AssertionError: (False, None) != (True,
'llama3.1:8b')`; `'SimpleNamespace' object has no attribute 'llm_ok'`). On a full install
the stack built completely, so nothing leaked — the operator's suite was green while the
09-20 container's was not. `_stack` is a `@contextmanager` now, and
`tests/test_ops_doctor_stack_leak.py` makes the fourth `patch()` raise and asserts the
first three are restored.

**Proof of the class, not the instance.** `py -m scripts.ops test --order reverse` and
`--order shuffle --seed N` run the suite in-process in another order (`core/suite_order.py`);
CI gained a reversed leg. Its **first** run found two more leaks nobody had reported:
`run_discovery` stores results in the *file-backed* signal cache shared by every test, so
two tests discovering the same topic string read each other's variants (the suite now runs
with `DISCOVERY_CACHE=false`; the two tests that assert the cache's semantics opt in); and
`tests/test_tts_edge` armed `_FakeCommunicate.fail = True` to prove a fallback and never
disarmed it (shared `setUp` now resets the fake).

| Order | Before (`ca0aed2`, clean worktree) | After |
|---|---|---|
| default | 3,501 tests · 8 failures | 3,526 tests · 8 failures |
| reverse | not runnable | 3,526 · **the same 8** |
| shuffle, seed 1 | not runnable | 3,526 · **the same 8** |

All eight failures are this container's environment, not the code: four
`test_operator_shell` (the `fastapi` extra is not installed here), three `test_tts_synth_seam`
and one `test_next15` (no `ffmpeg` binary on PATH). The same eight fail on the clean
`ca0aed2` worktree; none appear on a CI-shaped install. The nine listed in the first
after-run included one this wave caused and fixed before commit (a test that asserted the
discovery cache's semantics without turning it on).

### 1.2 One reset point for process-global state (#827)

The code-health survey found ~35 module-level mutables in `core/` and `apis/`, about a
dozen with **no reset path at all** — `llm_router._clients` (captures the first API key it
sees), `grade_calibration._ACCURACY_CACHE`, `analyst_accuracy._HIT_RATE_CACHE`,
`vault_relevance._config_cache`, the IGDB/Twitch OAuth tokens, `youtube_api._warmup_started`
— and another dozen reset by hand in whichever test file happened to notice. `core/process_state.py`
is one registry: twenty-three modules register an IO-free reset at import (**state, not
resources** — a probe, token, client or breaker resets; a loaded model, a font or a
configured logger does not), and `tests/__init__.py` calls `reset_all()` before every test.
`tests/test_process_state.py` pins it with an alphabetically-ordered pair: `test_a` warms
the probe cache, `test_b` must see `None`.

### 1.3 Tests that were green while checking nothing (#829)

- `test_tts_provider_report.test_does_not_touch_experiments_file` and
  `test_ytdlp_quiet.test_the_logger_swallows_error_lines` had **no assertion**. They now
  assert the file is untouched and that nothing reached stdout/stderr.
- `test_router_vision` and `test_thumbnail_scorer_smoke` skipped on "Pillow not installed"
  — Pillow 12.3 is a pinned hard dependency. Under `CI=true` a missing Pillow now fails
  (`tests/optional_deps.py`, the `qt_support` pattern from #729).
- `test_ascii_art` skipped three tests with a reason saying the mascot file is gitignored;
  it is tracked (52 lines). A checkout that lost the file would have gone green.
- `test_next15_wave2` re-ran another module's test method on a bare instance, skipping
  its `setUp` and reporting under the wrong name.
- `tests/__init__.py` did not blank `OLLAMA_MODEL`/`OLLAMA_BASE_URL`; `.env` loads without
  override, so an operator box with Ollama configured could make a real localhost probe
  from any test using `clear=False`. Blanked.
- A partial install produced ~90 import errors across ~470 tests and a real failure could
  not be told from a missing wheel. The suite now prints one line naming the missing
  optional modules. (Full skip-not-error across ~90 transitively failing modules was
  judged not worth the churn.)

Isolation bases are still duplicated rather than shared (`GovernorCase` copied in
`test_elevenlabs_quota.py`, `_IsolatedStateCase` in two files, nine files patching
`QUOTA_STATE_FILE` by hand) — left as is; the registry addresses the class of bug they
were each written against.

## 2. Type checking: a ratchet instead of a baseline nobody watched (#833)

CI ran `mypy` with `continue-on-error`. The count went ~94 (June) → 135 (September) with
nothing to notice. `scripts/mypy_ratchet.py` runs mypy over CI's directory list
(`analytics apis core config storage desktop`, `--no-incremental` because a stale
`.mypy_cache` under-reported by 24 on the same tree), compares to `mypy_baseline.txt`,
and **fails on increase**; on a decrease it prints the new number so the baseline can be
lowered in the same commit. The typecheck job is blocking for the first time.

| | Before | After |
|---|---|---|
| mypy errors (pinned 1.13.0, cache-free, CI dirs) | 129 in 62 files | **129** — this wave added none |
| enforced | no (`continue-on-error`) | yes — may fall, never rise |

Two measurement traps, recorded because both nearly became the baseline: a stale
`.mypy_cache` under-reported by 24 on the same tree (the ratchet runs `--no-incremental`),
and this box had mypy 1.19.1 on `PATH` reporting 135 where the pinned 1.13.0 reports 129
(the ratchet runs the interpreter's install, which is what CI has). Scope is still 6 of
~11 packages and the `video.*`/`publishing.*` override is dead config — #833's open half.

## 8. Method note

Two measurements in this session were wrong before they were right, and both are worth
recording because they are the shape this repo keeps meeting. The first dependency
install failed on one transitive wheel and reported success loudly enough that the
"baseline" I took was the crippled suite; the fix was to compare against a clean worktree
in the *same* environment, twice. The first mypy comparison differed by 24 errors between
two directories in one environment because of `.mypy_cache`; the ratchet runs
`--no-incremental` because of it. A number is only a measurement when you know what
produced it.
