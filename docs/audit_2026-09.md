# Grand audit — 2026-09

> **Class:** snapshot · **Status:** frozen · **Reviewed:** 2026-09-20

Point-in-time verdict on `content_machine` at `a4964b1`, 106 commits, two months old.
Successor to [audit_2026-08.md](audit_2026-08.md) and to the June
[assessment.md](assessment.md). Every number below was measured in this session, not
carried forward from an earlier doc — that habit is itself one of the findings.

Forward plan: [master_plan.md](master_plan.md). Docs conventions this audit produced:
[docs_standard.md](docs_standard.md).

## 0. Verdict in one paragraph

The engine is more capable than its documentation can describe and better tested than
its test suite can prove. Two months produced ~89k lines of Python and ~114k words of
docs, and both grew faster than the structures meant to keep them honest: `core/` is 149
modules with no internal seams, the docs corpus had no index and five naming
conventions, and the suite's result depends on the order the tests happen to run in.
None of this is decay — it is the cost of a fast, productive two months, and all of it
is mechanically fixable. The one finding that is not cosmetic is §1.3: a set of tests
written to guard a real live-run outage stops guarding it when the full suite runs.

## 1. Code

### 1.1 Scale

| | |
|---|---|
| Python, total | ~89,000 lines |
| Source | ~59,600 lines |
| Tests | ~29,400 lines across 254 `test_*.py` files |
| `core/` | 149 modules, 32,701 lines — **55% of source, one flat package** |
| `apis/` | 65 modules, 10,068 lines |
| Largest modules | `core/ui.py` 1,759 · `scripts/ops.py` 1,326 · `core/review_booth.py` 1,111 · `core/content_engine.py` 1,097 · `core/best_bet.py` 996 |

`core/` is the finding. It holds the router, the TTS path, the vault, the breakers, the
UI, the report card and the notifier as peers in one namespace. Nothing is wrong with
any single module; the package has simply stopped communicating structure, and a new
module has no obvious wrong place to go.

### 1.2 The three non-blocking baselines

CI blocks on ruff and the unittest suite, and reports without blocking on mypy,
pip-audit and coverage. That posture is right. The baselines have drifted:

- **mypy: 136 errors across 89 files** (of 255 checked). [assessment.md](assessment.md)
  recorded "~94 mypy errors" as tracked debt in June. It has grown ~45% since, which is
  what a non-blocking baseline does when nothing ratchets it.
- **ruff is pinned at 0.8.4** in `.github/workflows/ci.yml`, `pyproject.toml` and
  `.pre-commit-config.yaml` — consistently, which is better than most repos manage. It
  is also roughly nine months old. Running current ruff (0.15.8) reports **28 lint
  findings and 28 files needing reformat**. Neither is a CI failure today; both are the
  bill for a deferred upgrade, and the bill grows.
- **627 `except Exception`** in `core/`, `apis/`, `analytics/`, `storage/`, `video/`,
  `publishing/`. June tracked "~18 silent" ones. The fail-open-made-visible work (O11/O12)
  addressed the reporting, not the surface area. There are zero `TODO`/`FIXME` markers in
  the codebase — debt here is carried in docs and broad excepts, not in comments.

### 1.3 The suite is order-dependent — and it silences a real guard

This is the one finding that should change behaviour this week.

`tests/test_run69_fixes.py` was written, tests-first, against a named live-run outage:
run 70 died 71 seconds into discovery because Free mode reported `llm=ollama OK (local
$0)` while the daemon had nothing pulled. Thirteen tests pin that fix.

- Run the file alone: **13 of 13 pass.**
- Run the full suite: **5 of them fail.**

Cause: `core/llm_router._ollama_probe_cache` (`core/llm_router.py:217`) is a hand-rolled
module global, not an `lru_cache`. Once any earlier test warms it, patching
`ollama_installed_models` no longer changes what `run_mode._ollama_ready()` sees.
`tests/test_run_mode.py` and `tests/test_free_doctor_probe.py` reset the global by hand;
`tests/test_run69_fixes.py` does not, and nothing makes that omission visible.

Two things follow. First, the suite's verdict depends on discovery order, so a future
reordering can flip results with no code change. Second — and worse — this is precisely
the [decisions.md](decisions.md) §18 shape the repo already named: *something reporting
healthy while being broken*, now applied to the tests themselves. Green does not
currently mean the run-70 guard is holding.

Fourteen test files call some `cache_clear()`; the pattern is understood here. What is
missing is a single place that resets **all** process-global state between tests.

### 1.4 Optional dependencies error rather than skip

On an environment without the full install, the suite produces **263 errors** — 221
`ModuleNotFoundError` (149 `sqlalchemy`, 38 `bs4`, 13 `googleapiclient`, 11
`elevenlabs`, 8 `PIL`), plus the import-chain fallout. CI installs everything, so CI is
unaffected; a contributor or agent on a partial environment sees a wall of red and
cannot separate a real failure from a missing wheel. Two of this session's seven
non-import failures (`test_engagement`, `test_seo_tags`) were themselves downstream of
`apis.topic_scorer` failing to import `sqlalchemy` — they look like logic bugs and are
not.

### 1.5 What is genuinely good

Stated plainly, because an audit that only lists faults will be read as a fault list and
acted on as one:

- **The signal contract.** `make_signal()` plus `register_signals.py` gives every
  discovery source one shape, one cache, one breaker, and concurrency that a new signal
  inherits for free. This is the best idea in the repo.
- **`decisions.md` as load-bearing ADR-lite.** 23 docs and `CLAUDE.md` cite it by
  section number, and sections are cited from code comments. Reasoning is recoverable.
- **Directory-scoped `CLAUDE.md`.** `tests/` and `apis/` carry their own rules next to
  the code they govern.
- **Rules enforced as hooks, not paragraphs.** `.githooks/commit-msg` rejects agent
  co-author trailers because a written rule demonstrably failed once. That instinct is
  the model for everything in [master_plan.md](master_plan.md) M1.
- **Tests-first against named live runs.** `test_run69_fixes.py` opens by describing
  runs 69 and 70. That is how regression suites should read — which is exactly why §1.3
  matters.
- **`tests/test_docs_lint.py` already existed.** Docs were already partly
  machine-checked before this audit; the standard extends a habit rather than inventing
  one.

## 2. Documentation

The corpus, measured today: **46 files in `docs/`, 862,595 bytes, ~114,000 words**, plus
`README.md`, `CLAUDE.md`, `AGENTS.md`, `ROADMAP.md` at the root.

### 2.1 Findings

1. **No index existed.** Nothing in the repo listed what the 46 docs were or which of
   them was still true. Fixed in this pass: [README.md](README.md).
2. **48% of the corpus is five files.** `roadmap.md` (169,809 B), `planning_log.md`
   (78,142), `change_log.md` (76,159), `HANDOFF_SYNOPSIS.md` (46,642),
   `decisions.md` (43,935). `roadmap.md` is 1,774 lines with a **single 1,084-line
   section** ("Next up — all open items", 386 done / 178 open checkboxes). No reader,
   human or agent, loads that to answer a question.
3. **Eight roadmap-shaped docs.** `roadmap.md`, `ROADMAP.md`, `content_intelligence_roadmap.md`,
   `intelligence_phase.md`, `groundwork_2026Q3.md`, `strategy_2026H2.md`,
   `next_ideas_2026-07.md`, `tool_integration_plan.md`. Four audit-shaped docs. A reader
   cannot tell which is current from the filename.
4. **15 docs have not been touched since the repo's first commit** (2026-07-10) — never
   revised in the project's entire life, while describing a system that changed under
   them 81 times in August alone.
5. **Twelve different test counts are live simultaneously** across the corpus: 363, 374,
   905, 1125, 1382, 1411, 1433, 1969, 1985, 2010, 2118, 2160. Every one was true once.
   `assessment.md` says 363 in its table and 1,433+ in its addendum, in the same file.
6. **Five filename conventions**: 27 `snake_case`, 7 `kebab-case`, 3 dated, 1
   `SCREAMING_CASE`, and `strategy_2026H2.md` / `groundwork_2026Q3.md` in a fifth style.
7. **Two orphans** with zero inbound links: `n8n_recipes.md`,
   `scope_feature_store_and_research_v2.md`.
8. **Three names for the product**: "Content Machine" (19 docs), "Content OS" (14),
   "Content Intelligence Platform" (8).
9. **Formatting drift.** `decisions.md` has a median line length of 235 characters and
   jumps H1 → H3; `roadmap.md` has a 1,192-character line. Unwrapped prose makes diffs
   unreviewable, which is how stale claims survive review.

### 2.2 Root cause

Not neglect — the opposite. Every doc was written because a session needed one, and
nothing ever said where a new doc goes or when an old one stops being true. Absent that,
"write a new doc" is always cheaper than "find and update the right one", and a corpus
of snapshots accumulates that all claim the present tense. The fix is not tidying; it is
a rule about class and status, applied on write and checked in CI.

That is [decisions.md](decisions.md) §18, and it is the organising idea of the master
plan.
