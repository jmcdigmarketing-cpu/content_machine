# Own review — 2026-09-26: rework, duplicates, and a guard

> **Class:** snapshot · **Status:** frozen · **Reviewed:** 2026-09-26

The operator dropped the external Codex / Astra review ("if it hasn't been done then do it
yourself") and asked three questions: which ideas can be consolidated, where a fix was
erased by a newer idea, and whether the project needs a new system. This is that review,
done from `git log`, the backlog, the logs and the code on `main` at `4e4261e`, with every
number measured on the day. Companion to [audit_2026-09-26.md](audit_2026-09-26.md),
which scores the system; this one is about how work is lost.

## 1. Verdict

Yes on all three. Work is lost in two ways, and both have one root: **the same idea lives
in many private copies**, and a fix is tested only where it was made.

- A **later change undid an earlier fix** at least five times, each found only after it
  shipped (section 2).
- A **fix reached one copy and not its siblings** - still live today in two families
  until this wave (section 3).
- The codebase **accretes**: since 2026-08-01, source grew +46,226 / -3,412 lines (13:1),
  to 270 documented env flags and 141 ops verbs. New ideas are added beside old ones, rarely instead.

The new system is small: one shared module per repeated idea, and a **regression corpus**
that replays every live-run defect on every CI run (section 5).

## 5. The new system

**Regression corpus** - `tests/regression_corpus.json`, replayed by
`tests/test_regression_corpus.py` and `py -m scripts.ops regressions [file]`.

- One case per live-run defect: a pure call (`module:function`, args), what must stay true
  (`equals`, `contains`, `excludes_any`, ...), the backlog item and why. No network, no
  data files; `patch_raise` keeps an LLM call out.
- A case lives apart from the fix, so deleting or rewriting the fix does not delete it.
- When a fix has siblings (a tokenizer, a query builder), each sibling gets a case too.
- `ops regressions <file>` lists the old fixes guarding a file before you change it.
- Seeded with 28 cases: 13 past fixes (run 66, 69, 77, 98, the wave 15 audit) and 15 sibling
  cases that failed on `4e4261e`.
- **Proven able to fail:** with "what" and "why" removed from `FUNCTION_WORDS`, 14 of 28
  cases went red across 14 modules; restored, 28 of 28.

**One topic-text module** - `apis/topic_tokens`: `FUNCTION_WORDS`, `content_tokens(min_len=)`,
`title_phrases`, `search_query(drop=, max_len=, always_entity=)`. A test fails when a module in
`core/`, `apis/`, `analytics/` or `video/` defines a stopword list that does not derive from
`FUNCTION_WORDS`, except four allowlisted with a reason (entity-leading verbs, title pins,
script-similarity vocabulary, visual keywords).

**The rule** (CLAUDE.md, the next-five and tdd skills): a live-run defect adds a corpus case,
plus one per sibling; topic words come from `apis/topic_tokens`, never a private list.
